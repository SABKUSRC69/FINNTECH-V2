# Student-project real-use mode

The owner's current scope supersedes the former production readiness gate: free hosting sleep and no SLA are accepted. Brevo, Drive/Gmail automation and machine-loss recovery are optional, deferred integrations. Their missing secrets do not block password-mode registration/login. No claim of automated backup or recovery readiness is made.

Explicit server configuration: `TRACKER_REAL_AUTH_MODE=email-password`, `TRACKER_RECOVERY_MODE=off`, `TRACKER_RUNTIME_MODE=cloud-real`, `TRACKER_DATA_MODE=real`. There is no implicit downgrade when email fails. Existing `verified-email` mode still requires its verified sender/outbox secrets and retains all recovery protections.

Password mode uses Better Auth 1.7.7, password length 12–128, hashed passwords and genuine sessions. `emailVerified` stays false. An email is an account identifier, not proof of mailbox ownership. Verification/reset endpoints are absent; no recovery email is sent. Forgotten passwords cannot be recovered in this mode. Keep a password-manager copy and personal exports. Future email verification needs a separately reviewed activation.

Use a fresh Neon database `finntech_personal` and separate login role `personal_app`, without superuser, createdb, createrole or bypass-RLS privileges. Never reuse `finntech_beta` or `beta_app` as the personal runtime connection. `scripts/real-use-prepare.mjs` refuses a nonempty schema and records its runtime boundary. Initialize with registrations closed. HTTPS exact origin, secure HttpOnly SameSite=Lax cookies, HTTP/WS session checks, blocked-account lifecycle and server-derived ownership remain required. The lifecycle enrollment row does not mean an email is verified.

Initially set `TRACKER_REAL_ENROLLMENT_MODE=staging` and `TRACKER_REAL_STAGING_EMAILS` to only synthetic acceptance accounts. After actual HTTPS isolation, financial operations, export and persistence checks pass, use `TRACKER_REAL_ENROLLMENT_MODE=public`, `TRACKER_REAL_REGISTRATIONS_OPEN=true`, `TRACKER_REAL_ACCEPTANCE_APPROVED=review-approved` and remove the staging list. This acceptance flag records the owner's conditional activation authorization, not a separate third-party review certificate. Keep account limit 100 and storage gate 256 MiB. Both configurable caps pause new writes/registration rather than deleting data. The signup cap is serialized across processes and signup user/account/lifecycle/session creation rolls back together on failure.

Deploy a separate Free Render service from an isolated release branch and `Dockerfile.real`; do not change the DEMO service environment/database. Do not enable a paid instance/disk. Render's free workspace runtime quota is shared across free services; sleeping and quota suspension are accepted. Persist all records in Neon, not the ephemeral Render filesystem.

Logout ends a session but retains records. Account deletion remains an explicit password/consent request which blocks the account and revokes sessions; administrator purge/retention integrations remain separate. JSON exports contain financial data, not authentication credentials, and are unencrypted; keep them private. Export is not a full database or account recovery backup. Optional encrypted database backup tooling remains available but is not configured or claimed ready.

Acceptance evidence must identify actual commands/exit codes and separate local synthetic checks from cloud checks. Two independent cookie jars are distinct sessions; do not describe them as two physical browsers. Restart/redeployment must retain both owners' mappings and exact values. Never publish test passwords, cookies, environment files, raw exports or backup keys.
