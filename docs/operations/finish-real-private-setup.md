# Private setup checklist — 8 ตุลาคม 2026

ยังไม่มี Brevo/Drive setup ตามคำตอบเจ้าของ เครื่องอื่นและ key custody ให้พักไว้ก่อน จึง **ยังไม่เปิด public หรือ schedule จริง** ไม่ส่งค่าต่อไปนี้ในแชต ให้เก็บใน private files/secret store และแจ้งเพียง path เมื่อพร้อม ไม่มีบริการเสียเงินหรือบัตรเครดิต

1. **Staging แยกจาก Beta**: เสนอ Render service ชื่อ `finntech-real-staging` + Neon project `finntech-real-staging`, database `finntech_personal`, app role `personal_app`. นี่คือชื่อที่เสนอ ไม่ใช่ resource ที่สร้างแล้ว ตรวจ Free quota/availability ก่อนสร้างหลัง review. Target IDs, hostname และ HTTPS origin ต้องอ่านจากบริการจริงเท่านั้น ใช้ตัวแปรทั้งหมดใน [real-use setup](real-use-setup.md) เพิ่ม `TRACKER_REAL_ENROLLMENT_MODE=staging`, `TRACKER_REAL_REGISTRATIONS_OPEN=false`, `TRACKER_REAL_STAGING_EMAILS` เป็น CSV อีเมลทดสอบที่เจ้าของควบคุม ไม่เกิน 20 ราย. รายชื่อไม่อยู่ frontend/health. ใช้ fresh `DATABASE_URL`, `BETTER_AUTH_SECRET`, `TRACKER_RECOVERY_OUTBOX_KEY`; ห้าม DEMO flags หรือ synthetic recovery.
2. **Brevo Free**: เจ้าของสมัคร/ยืนยัน sender ใน mailbox เอง เก็บ `TRACKER_MAIL_API_KEY`, `TRACKER_MAIL_SENDER`, `TRACKER_MAIL_SENDER_CONFIRMED=owner-verified`, `TRACKER_MAIL_PROVIDER=brevo`, `TRACKER_RECOVERY_MODE=real-email`, `TRACKER_REAL_SUPPORT_EMAIL`. Support email เปิดเผยใน UI จึงแยกจาก private Gmail alerts. ต้องทดสอบ verify/reset/notice ถึง inbox/spam จริง รวม delay/expiry/replay/HTTP+WS revocation. Provider 201 ไม่ใช่ delivery. Free 300/day; โควตาบัญชีจริงและ free-sender eligibility ยังไม่ตรวจ [Brevo limits](https://help.brevo.com/hc/en-us/articles/208580669-FAQs-What-are-the-limits-of-the-Free-plan).
3. **Drive และ backup**: private owner-only NTFS ACL สำหรับ env/archive/key; key เป็น random 32 bytes อยู่แยกจาก archive และต้องมี recovery copy นอก Windows profile. ตั้ง `FINNTECH_BACKUP_DATABASE_URL`, `FINNTECH_BACKUP_DATABASE_ROLE` เป็น read-only role แยก app, `TRACKER_REAL_DATABASE_HOST`, `TRACKER_REAL_DATABASE_NAME`, `TRACKER_REAL_DATABASE_ROLE`, `TRACKER_ORIGIN`, `FINNTECH_BACKUP_DIRECTORY`, `FINNTECH_BACKUP_KEY_FILE`, `FINNTECH_BACKUP_PRIVATE_DIRECTORY_CONFIRMED=owner-only`, `FINNTECH_BACKUP_LAST_RECEIPT_FILE` เป็น absolute JSON path ภายใน archive directory. เพิ่ม `FINNTECH_DRIVE_CLIENT_ID`, `FINNTECH_DRIVE_CLIENT_SECRET`, `FINNTECH_DRIVE_REFRESH_TOKEN`, `FINNTECH_DRIVE_FOLDER_ID`, `FINNTECH_PRIVACY_DRIVE_FOLDER_ID` เป็นสอง private folders ที่ grant ให้ OAuth app จริง (scope `drive.file`). อย่าใช้ folder ที่ shared หรือเก็บ key รวม ciphertext.
4. **สร้าง receipt/registry อย่างตรวจซ้ำได้**: `FINNTECH_DRIVE_SETUP_JOURNAL` เป็น absolute private file ใหม่, `FINNTECH_DRIVE_SETUP_CONFIRM=private-existing-folders-only`; รัน `node --env-file="<private-setup-file>" scripts/real-drive-setup.mjs`. อ่าน receiptId/registryId จากไฟล์ส่วนตัวเข้า `FINNTECH_DRIVE_RECEIPT_FILE_ID` และ `FINNTECH_PRIVACY_REGISTRY_ID`; ไม่ส่งไฟล์ในแชต. ทำ privacy initialization ตาม runbook ก่อนมีคำขอลบ. ตรวจ download/hash/AES และ provider conditional-write ETag จริงก่อนกล่าวว่า workflow พร้อม.
5. **Gmail alerts นอกเครื่อง**: เก็บ `FINNTECH_BACKUP_ALERT_EMAIL` เป็น Gmail จริงของเจ้าของ ร่วมกับ Brevo sender/key และ Drive read authorization ใน secret store ของ independent runner. Template `docs/operations/templates/real-backup-monitor.yml` ยังไม่ activate. ตรวจ GitHub plan/free minutes/budget $0 ก่อนใช้งาน (4 runs/day × timeout 2min ≈ 240min/month ไม่รวมข้อจำกัดอื่น) [GitHub billing](https://docs.github.com/en/billing/concepts/product-billing/github-actions). ทดลอง receipt หาย/ล้มเหลว/เกิน 24h/OAuth หมดอายุ และยืนยัน Gmail ถึงจริง. ไม่มี web keep-alive. Hosted cron อาจล่าช้า; ไม่ใช่ guaranteed monitoring SLA.
6. **ก่อน schedule**: ต้องมี `FINNTECH_BACKUP_ACCEPTANCE_FILE` เป็นหลักฐานส่วนตัวจากการตรวจจริง ระบุ `keyFingerprint`, `checkedAt` ISO ไม่เกิน 7 วัน, `machineLoss`, `offDeviceRestore`, `gmailAlertReceived`, `independentWatchdog` เป็น `PASS` ตามผลจริง ห้ามสร้าง PASS เพื่อข้าม gate. เจ้าของข้าม machine-loss ตอนนี้ ดังนั้น installer จะยังไม่ผ่าน readiness. เมื่อพร้อมรันตรวจด้านล่างก่อนเพิ่ม `-Install`.

คำสั่งที่ไม่พิมพ์ค่า secrets:

```powershell
node --no-strip-types --env-file="<private-file>" scripts/real-private-setup-check.mjs inventory
node --no-strip-types --env-file="<private-backup-file>" scripts/real-private-setup-check.mjs backup
powershell.exe -NoProfile -File scripts/real-backup-install.ps1 -PrivateEnvFile "<private-backup-file>"
```

`inventory` แสดงเฉพาะชื่อตัวแปรที่ขาด; exit1 เมื่อไม่ครบ. `mail`/`watchdog` แสดงเพียง configuration present และยัง exit1 จนมี actual acceptance แยก ไม่รับรองส่งถึงจากการมี key. `backup` ตรวจ target/Drive capacity/private folder และหลักฐาน review;ไม่สร้าง fake delivery/restore. ห้าม log env, `set`, `Get-ChildItem Env:` หรือ raw provider error. ยังขาดเพียงข้อมูลจริงตามข้อ 1–6 และการอนุมัติ staging deployment ไม่ต้องตอบ preference เดิมอีก.
