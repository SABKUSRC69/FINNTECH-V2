# Real-use operator, deletion, retention และ incident

สถานะการทดสอบ: PostgreSQL 18 สังเคราะห์ 30 tables/full schema restore, scoped deletion/rollback/foreign-owner preservation, registry replay และ Windows trigger/mutex ผ่านในเครื่อง. **Actual Brevo/Drive/Neon restore/independent Gmail runner/HTTPS deployment ยัง NOT TESTED**. ใช้ร่วมกับ [private checklist](finish-real-private-setup.md). ห้ามนำ synthetic accounts ไปฐานจริง.

## Deletion ที่ทำงานแล้ว

ผู้ใช้ที่ verified/session valid เปิดหน้าบัญชี ส่ง current password + consent + original UUID receipt. Server derive owner จาก session, lock auth user และ exclusive dataset รอ pending writes, recheck password/session, block recovery, revoke sessions/challenges/outbox ใน transaction เดียว. API ใหม่ real-only, exact Origin, JSON ≤16KiB, bounded persistent budgets. UI ล็อก navigation เมื่อผลไม่แน่นอน; reload เก็บเฉพาะ UUID ใน sessionStorage, ตรวจ status ด้วย key เดิม, ไม่เก็บ password. คำขอนี้ปิดบัญชีทันที ไม่ใช่ grace period 7 วันตาม proposal เก่า; policy นี้ยังต้อง review ก่อน public.

Operator login แยก API role. ตั้ง `FINNTECH_PRIVACY_DATABASE_URL/ROLE/NAME`, `TRACKER_REAL_DATABASE_HOST`, `FINNTECH_PRIVACY_KEY_FILE` (random 32 bytes แยก backup key), `FINNTECH_PRIVACY_DRIVE_FOLDER_ID`, `FINNTECH_PRIVACY_REGISTRY_ID`, OAuth variables. เก็บ key/registry ID แยกจาก old DB backup และรักษา key custody นอกเครื่อง.

- Provision ครั้งเดียวด้วย real app/migration admin private env: `FINNTECH_PRIVACY_PROVISION_CONFIRM=new-operator-only`, `node --env-file="<private-file>" scripts/real-privacy-provision.mjs`. Operator URL ต้อง target เดียวกัน ใช้ role ใหม่ ไม่แก้ role เดิม. Grant เฉพาะ SELECT marker/cases และ EXECUTE scoped functions; ไม่ให้ DELETE tables/CREATE ROLE. Restore target ต้อง provision role/grants อีกครั้งเนื่องจาก pg_dump ไม่พก cluster roles/ACL.
- Initialize registry ก่อนมี cases: `FINNTECH_PRIVACY_ACTION=initialize-registry`, `FINNTECH_PRIVACY_REGISTRY_JOURNAL=<absolute private path>` แล้วรัน `scripts/real-privacy-operator.mjs`. Ciphertext เก็บก่อน send และ reuse ID/bytes. Registry AES-GCM ผูก dataset UUID และมีรายการ case IDs/hashes อยู่ใน private Drive folder แยก retention archives.
- Inventory: `FINNTECH_PRIVACY_ACTION=inventory` แสดง counts เท่านั้น. ตรวจ case ใน private operator session โดยไม่ export personal records/log credentials.
- หลังตรวจ consent/case และ review: `FINNTECH_PRIVACY_ACTION=publish-purge`, `FINNTECH_PRIVACY_CASE_ID` กับ `FINNTECH_PRIVACY_CONFIRM_CASE` ต้องเท่ากัน. Operator reserve/persist file ID+ciphertext ก่อน upload, download/authenticate, append encrypted registry ด้วย If-Match ETag, ตรวจกลับ แล้วจึง purge transaction เฉพาะ owner. Lost response รัน case เดิม; mismatch/unsupported ETag/failure ให้หยุดและเก็บ journal เดิม. Actual Drive ETag semantics ยังต้องพิสูจน์ก่อนใช้จริง.

Database guards ไม่ถูก disable. Audit/idempotency DELETE ยอมเฉพาะ case PURGING + same transaction ID + operator login + target owner. Legacy imports/DEMO refused. SQL purge rollback ทั้งชุดเมื่อ error; operator ไม่มี generic DELETE. Minimal tombstone เก็บ UUID/เวลา/status/hash ไม่มีอีเมล/ชื่อ/password/financial records. ประวัติการเงินทั้งหมดของ owner ยังอยู่ใน encrypted old backups จน retention ครบ; ไม่อ้างลบทุกสำเนาทันที. Registry/tombstones ห้าม prune อัตโนมัติขณะยังมี archive เก่าที่อาจนำคืนได้; หลัง archive ทุกชุด retired ต้อง review disposal แยก.

## Full restore และกัน resurrection

1. ปิด target runtime และเลือก Neon database ใหม่ว่าง แยก source พร้อม private `FINNTECH_RESTORE_DATABASE_URL/HOST/NAME/ROLE`, `FINNTECH_RESTORE_ARCHIVE_ID`, `FINNTECH_RESTORE_ARCHIVE_SHA256`, backup key/OAuth และ `FINNTECH_RESTORE_CONFIRM=new-isolated-empty-target`.
2. `node --env-file="<private-restore-file>" scripts/real-full-restore.mjs`: ตรวจ target identity/schema/types ว่าง, private Drive ownership/parent/hash, decrypt ก่อน `pg_restore --single-transaction --exit-on-error`. Plaintext อยู่ RAM/stdin; ไม่ reset/drop. ถ้าล้มเก็บ targetและเลือก targetใหม่หลังตรวจ ห้ามเขียนทับ.
3. ใช้ `scripts/sql/real-restore-evidence.sql` เทียบครบ tables/columns/NUMERIC/constraints/functions/triggers/indexes/sequences กับหลักฐาน backup. Source ต้อง freeze writes ระหว่างการเทียบ live หรือใช้ evidence ที่ถ่ายใน snapshot เดียวกัน; อย่าเปรียบเทียบ snapshot กับ live ที่เปลี่ยนแล้วและสรุป PASS. เครื่องทดสอบทำขณะ quiescent; 30 tables matched.
4. Provision operator ที่ restore target. ใช้ `FINNTECH_PRIVACY_ACTION=restore-replay`, `FINNTECH_PRIVACY_RESTORE_CONFIRM=isolated-restore-only`; target database name ต้องต่าง archive marker. โหลด registry ล่าสุดจาก Drive (ห้ามใช้ registry จาก snapshot) ตรวจ authenticated inventory ครบทุก ID/hash แล้ว replay cases ก่อนเขียน restore receipt. Registry หาย/รายการไม่ครบ/ถูกแก้ระหว่างอ่าน => fail closed; target ยังไม่ serve.
5. ตรวจ record/ownership/financial/auth/ledger/audit/receipt ของเจ้าของที่เหลือ, deleted owner ต้องไม่มี, ตรวจ private roles/ACL. หลัง staging review เท่านั้น: `FINNTECH_RESTORE_DATASET_ID`, `FINNTECH_RESTORE_LEDGER_SHA256` จาก receipt, `FINNTECH_RESTORE_ACTIVATION_CONFIRM=reviewed-staging-only` และ full real config ของ target ที่ `staging`/registration false. `scripts/real-restore-activate.mjs` ต้อง receipt ≤1h, no pending cases, real-only; invalidate all snapshot sessions/challenges/outbox แล้ว rebind marker ใน transaction. Public signup ไม่เปิด.

ขณะ replay/rebind ต้องหยุด operator purges ต้นทางและหยุด writes ระหว่าง cutover; ตรวจ registry ล่าสุดอีกครั้งก่อนสลับ target. ไม่มี automatic cutover. ขั้นตอน cloud นี้ยังต้อง actual acceptance. การ copy key ไปอีก directory ใน Windows เดิมไม่ใช่ machine-loss test; เจ้าของพัก drill นี้ไว้ จึงยังไม่รับรอง readiness.

## Backup runner/retention

Wrapper `real-backup-scheduled.ps1` load เฉพาะชื่อ env ที่อนุญาต, restore process env เมื่อจบ, ไม่ log sensitive errors. Mutex กันหลาย process; durable journal เก็บ phase/DUMP/UPLOAD/DONE และ original archive path. Failed/lost upload retry archive+reserved Drive ID เดิม (สูงสุดสอง attempts/run, backoff30s); failed publication/เครื่อง offlineตรวจจาก independent watchdog. รันสำเร็จภายใน24h ไม่ dumpซ้ำ. Windows task 02:00 local, signed-in owner, StartWhenAvailable, IgnoreNew, battery allowed, retry15minครั้งเดียว, limit15min. หาก logout/เครื่องปิด/Dockerไม่พร้อม ต้องเตือนจากนอกเครื่อง. Installer refuses missing acceptance และ existing task, ไม่แทนที่งานเดิม.

Retention: `FINNTECH_RETENTION_SCOPE=local|drive`, `FINNTECH_RETENTION_PLAN_FILE=<new private absolute path>`, `FINNTECH_RETENTION_DAYS=30` (7–90). `scripts/real-retention-cli.mjs` ครั้งแรก dry-run ไม่ลบ. อ่าน inventory/check hashes แล้วตั้ง `FINNTECH_RETENTION_APPROVE_SHA256` จาก digestแผนเดิมเพื่อ applyภายใน24h. ต้องมี current authenticated copy, recognized name+format+keyfingerprint+hash, private ownership. Local symlinks/changed files refused; Drive version/If-Match mismatch refused; lost DELETE response reconcile exactID. ไม่แตะ unrelated files, DB/volumes หรือ deletion registry. Old `pruneExpiredBackups` ปฏิเสธเพื่อบังคับ reviewed plan. มี unit tests แต่ actual Drive retention NOT TESTED.

## Incident และ rollback

- Email/Drive unauthorized หรือ quota: ปิด enrollment เป็น `closed` และล้าง allowlistพร้อมกัน; existing real recordsคงอยู่. ตรวจ coarse jobs/receipts. Do not resend new payload/key or reset database. Token/secret rotationผ่านprivate store; retained pending outbox/receipt hashesต้องมีแผน key compatibility. Auth-secret rotationเพิกถอนsessionsและเปลี่ยน deletion status HMAC; reconcile pending casesก่อน planned rotation หรือให้ operatorตรวจcaseส่วนตัวหลังincident.
- Backup failed/missed: ห้ามตั้ง receipt successด้วยมือ; ตรวจ original job/archive/journal, auth renewal, available storage. Alert acceptedต้องตรวจ Gmail receiptจริง. Independent runnerต้องอยู่ภายนอก Windows/Render. Cron delayed/disabledต้องมีการตรวจ account status;ไม่มี SLA.
- Rollback ใช้เฉพาะ release ที่เข้าใจ real boundary **และ deletion guards/blocked enrollment**. ก่อนเวอร์ชันนี้ไม่มี post-lock deletion check จึงไม่รับรอง rollback onlineกับ pending deletion; pause writes/runtime แล้ว review compatible binary/forward fix. ไม่ย้อน SQL migrationหรือลบ tombstones. ไม่กลับ Beta image/credentials. Fullrestoreต้อง replay current registry, invalidate oldsessionsและ reviewcutover.
- Runtime privateenv/key filesไม่อยู่ patch/image. ห้ามเปิด logs/provider bodies/raw backupsต่อสาธารณะ. เก็บ reviewer evidenceเฉพาะcounts/hashes/exit codes. หากkeyและเครื่องหายพร้อมกัน ciphertextกู้ไม่ได้; readinessยังBLOCKEDจนมีindependentcustody/drillจริง.
